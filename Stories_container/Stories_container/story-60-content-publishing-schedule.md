# Story 60: Content Publishing & Maintenance Schedule

**Epic:** Continuous Optimization
**Priority:** P2 — Medium
**Effort:** Small (Planning)
**Type:** Process Documentation (No Code Changes)

---

## Description

As the marketing/content team maintaining the website,
I should have a documented content publishing and maintenance schedule,
so that the website stays fresh, relevant, and continues to improve SEO rankings over time.

---

## Content Freshness — Why It Matters

- Google and AI agents prefer recently updated content
- Stale websites gradually lose rankings
- Regular publishing signals an active, authoritative business
- Blog posts (Story 21) and case studies (Story 23) need a publishing cadence

---

## Recommended Schedule

### Weekly
| Task | Owner | Details |
|------|-------|---------|
| Blog post | Content team | 1 post per week minimum (Story 21) |
| Social media post | Marketing | Share blog content on LinkedIn, YouTube |

### Monthly
| Task | Owner | Details |
|------|-------|---------|
| Content freshness review | Content team | Update dates, stats, any outdated info |
| New case study | Business team | 1 case study per month (Story 23) |
| Keyword performance check | SEO lead | Review Search Console data (Story 59) |
| Backlink outreach | Marketing | 2-3 directory submissions or guest posts |

### Quarterly
| Task | Owner | Details |
|------|-------|---------|
| Full SEO audit | SEO lead | Run Lighthouse, check all pages |
| Core Web Vitals check | Developer | Measure LCP, FID, CLS (Story 31) |
| Schema validation | Developer | Re-test all JSON-LD on Google Rich Results |
| Competitor analysis | Marketing | Review competitor keyword rankings |
| Content quality review | Content team | Audit for outdated claims or metrics |

### Annually
| Task | Owner | Details |
|------|-------|---------|
| Full website content refresh | All | Update all pages with latest data |
| Copyright year update | Developer | Update footer copyright year |
| SSL certificate renewal | IT/DevOps | Verify GitHub Pages SSL |
| Privacy policy review | Legal | Update for any regulatory changes |

---

## Content Ideas Pipeline

Maintain a running list of content ideas:
1. New product launches → product tab + blog post
2. Client success stories → case study section
3. Industry trends → blog posts
4. Engineering standards updates → technical content
5. Conference/event participation → blog posts + social media
6. Product updates → changelog/blog

---

## Acceptance Criteria

- [ ] Publishing schedule documented with owners and cadence
- [ ] Blog publishing cadence defined (minimum 1/week)
- [ ] Quarterly audit tasks listed
- [ ] Content ideas pipeline started
- [ ] Schedule shared with team

---

## Files to Modify

- None — this is a process documentation story
- Schedule can be tracked in a project management tool (Trello, Notion, Jira)

---

## Technical Notes

- Google's "freshness" algorithm rewards recently updated content
- Publishing frequency matters for blog indexing — consistent publishing = faster crawling
- AI agents prefer citing content that was recently updated (check `dateModified` in schema)
- This story has no website code changes — it is a team process document
